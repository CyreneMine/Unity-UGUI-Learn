# 第二阶段复盘：常用 UI 控件

本阶段对应课程第 12-27 节，目标是系统梳理常用显示与交互控件，并通过连续练习把多个控件组合到同一个场景中。

## 已学习控件

- `Image`：使用 Sprite 显示 UI 图像，理解不同显示与填充方式。
- `Text`、`RawImage`：显示文本与原始纹理。
- `Button`：注册点击事件，通过按钮触发游戏逻辑。
- `Toggle`、`ToggleGroup`：表示开关或互斥选项。
- `InputField`：接收玩家输入并响应编辑事件。
- `Slider`、`Scrollbar`：处理连续数值与滚动位置。
- `ScrollView`：通过 Viewport、Content 和 ScrollRect 展示超出可视区域的内容。
- `Dropdown`：通过选项索引切换状态。

## 完成的练习

1. Button 发射练习

   点击 UI 按钮调用玩家发射逻辑，同时保留鼠标右键发射。按钮与游戏逻辑共用同一个 `Fire()` 入口。

2. Toggle 音效开关练习

   使用 ToggleGroup 控制音效开启与关闭，两种发射方式都会遵守当前音效开关。

3. InputField 改名练习

   点击改名按钮打开面板，输入新名字并确认后更新场景中的玩家姓名。

4. Slider 音量练习

   Slider 使用 `0-1` 数值范围控制新播放的发射音效音量，并兼容 Toggle 音效开关。

5. ScrollView 背包练习

   点击背包按钮打开面板，动态创建 30 个物品并加入 Content，通过 ScrollView 查看超出可视区域的内容。

6. Dropdown 昼夜切换练习

   Dropdown 使用选项索引切换太阳角度，实现基础的白天与黑夜切换。

## 已形成的理解

- UI 控件负责接收交互和显示状态，具体游戏行为应尽量集中在明确的方法中。
- 通过代码注册事件时，需要避免重复注册，并确保 Inspector 引用已经绑定。
- 多个 UI 控件可以共同修改一份状态，例如 Toggle 控制音效开关、Slider 控制音量。
- 动态创建 UI 时，需要正确设置父节点，并根据内容数量调整 Content 尺寸。
- Dropdown 逻辑优先使用选项索引或明确状态，不依赖界面显示文字。

## 后续改进点

- 使用 `string.IsNullOrWhiteSpace()` 避免玩家提交空名字。
- 避免每次发射都动态添加和销毁 AudioSource。
- 后续使用 `GridLayoutGroup` 替代背包中的手动坐标计算。
- 背包只需要纵向滚动时，可以关闭 ScrollRect 的 Horizontal。
- 昼夜切换可以进一步控制灯光强度、颜色和环境光。
- 随着面板数量增加，需要逐步减少静态单例和面板之间的直接访问。
